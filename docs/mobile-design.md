# Android mobile boards

The user chose [mymind's mobile visual style](https://mymind.com/mobile), with two explicit changes: adjustable preview sizing and aligned rows/columns like desktop Papan. Standard Android Material behavior remains required. Reading this as a private reference board for visual collectors, in mymind's quiet notebook style with Papan's regular grid: ENERGY 1 / RHYTHM 1 / MOTION 1. This supersedes the earlier black/green mobile design.

Warm off-white separates white content cards with little framing; charcoal surfaces provide the same hierarchy in dark mode. A terracotta accent identifies actions and selection. The native scalable sans-serif keeps captions and controls legible. Papan's wordmark, collection strip and regular board supply the identity. Google's outlined Material phone/desktop/history/search/tune/add vectors replace the old framework icons; each names its real action or destination. No generated identity imagery is introduced.

Compact windows use Material bottom navigation for On phone, Desktop and Activity. Windows at least 600dp wide use a navigation rail. A compact toolbar holds Search and Board appearance; Paste link and secondary collection/connection actions live in its menu. Search appears when requested and Android Back closes it before leaving the board. A 56dp floating Add link action keeps capture available without a wide button over the collection. The duplicate collection heading is removed from ordinary boards. System, keyboard and floating-action insets reserve their own space.

RecyclerView uses equal-width columns, shared square media frames and 8dp gutters. Each title and source website sit inside the bottom of the preview; there is no separate caption block. The caption follows desktop Papan's `.tile-overlay`, `.tile-title` and `.tile-source` treatment: a continuous transparent-to-85%-black fade, regular 12sp title, 10sp muted source, 5dp between labels, 15dp side insets and 16dp bottom inset. The caption container has no background. Both labels always use one line with end ellipsis, and website names omit `www.`. The fade's midpoint is strengthened for readable phone text over a white image; its 50dp lead-in scales with the user's font size. This gradient serves media/text readability, with no flat opacity plateau. Captions stay visible on touch screens; desktop's hover reveal has no phone equivalent. Full title text remains available to accessibility and in details, where Open source retains the complete URL. Mixed image proportions, long titles, loading and failed previews cannot change row heights. Video/link/text placeholders use the same square frame and overlay; loading or failure status stays in the preview area while the website remains visible. Board appearance contains a native Material Preview size slider, Fill image frames switch, and Use phone setting/Light/Dark radio controls. Smaller frames fit more columns; larger frames fit fewer. Below 340dp, or when enlarged text cannot fit multiple readable cards, the grid uses one column. Width changes use the actual board area, including the tablet rail. Resizing retains the visible reference and off-screen cards recycle normally.

Preview size and frame fit are phone-only view preferences keyed by location and collection ID. The last selected collection IDs survive reopening. These preferences are separate from the local library, pending delivery, desktop collection settings and receiver protocol. Theme follows Android by default and can be changed explicitly; a theme change recreates the Activity through AppCompat's normal lifecycle, including protected-access clearing on backgrounding.

Paste and Android share intents use the same Material bottom sheet to choose a phone or desktop collection. Forms and confirmations use Material dialogs, outlined text fields, field errors and native password visibility controls. Cards, buttons, navigation and snackbars use actual Material components rather than drawn imitations. Controls retain at least 48dp touch targets. Text/error/status states accompany loading, empty, offline and failed-media states. Font scaling, accessibility descriptions and native focus/press feedback remain enabled.

On phone and Desktop are separate locations. Local collections and captured previews live in app-private storage and work without pairing. Choosing a phone destination commits the link before preview retrieval. Desktop shows only currently open collections, behind an explicit browsing preference. Choosing a desktop destination stores its stable ID with the pending link, including across restart and IP-address changes. A retry never silently switches to the desktop default. Legacy servers and offline default delivery remain explicitly labelled choices.

Protected desktop contents require phone-specific password authorization even if the desktop already unlocked them. Remote media stays in memory, and backgrounding clears the view and requests authorization removal. Desktop lock/close/revoke and 15-minute expiration block further reads. Protected boards, passwords and details use Android's secure-window flag. Android Activity shows pending deliveries and offers explicit retry/dismiss actions.

Local capture saves ordinary HTML titles and Open Graph thumbnails, plus direct JPEG/PNG/WebP/GIF images and MP4/WebM files up to 32 MiB. It does not run desktop's site-specific extractors or JavaScript. Failed capture retains the link and supports retry. There is no implicit synchronization; sending a local pin to desktop is explicit. Local collection encryption and `.papan` import/export are outside this version.

Guidance: [Android adaptive navigation](https://developer.android.com/develop/ui/views/layout/build-responsive-navigation), [Android dark theme](https://developer.android.com/develop/ui/views/theming/darktheme), [Android accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility), and [Material Components for Android](https://github.com/material-components/material-components-android/tree/1.13.0). Native verification and its limits are recorded in [verification.md](verification.md).
