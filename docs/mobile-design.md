Phone and Desktop are separate locations. Local collections and captured previews live in app-private storage and work without pairing. Choosing a phone destination commits the link before preview retrieval. Desktop shows only currently open collections, behind an explicit browsing preference. Choosing a desktop destination stores its stable ID with the pending link, including across restart and IP-address changes. A retry never silently switches to the desktop default. Legacy servers and offline default delivery remain explicitly labelled choices.

**Connections → Pair desktop** opens a native Material Nearby desktops dialog. Choose a discovered computer, compare the large six-digit code and explicitly allow pairing in desktop Papan. The request expires after two minutes; Cancel, backgrounding or QR fallback stops the phone worker and cancels unfinished requests. **Scan QR** remains available without discovery. Reconnecting the existing computer works with pending links; replacing it with a different computer remains blocked until those links are resolved. One desktop is active at a time.

Browsing and delivery recover a changed address through Android's native DNS-SD service. The phone verifies a fresh identity challenge using its existing pairing before saving a discovered endpoint; no bearer token is sent to an unverified discovered address. Recovery retains the key and each queued link's ID/destination. A concurrent manual address edit takes precedence over stale discovery. This reconnects the desktop connection; phone and desktop libraries remain separate.

Protected desktop contents require phone-specific password authorization even if the desktop already unlocked them. A random `X-Papan-Session` identity stays in memory across backgrounding, rotation and theme changes. Closing the main Activity ends it and requests scoped authorization removal; a killed process starts with a different identity even if its close request could not reach desktop. Passwords and session identities are never saved. Matching desktops retain access for that app session without the former 15-minute timeout. Desktop lock/close/revoke, protection changes and restart still block further reads; legacy clients keep their 15-minute grants. Backgrounding clears protected views and stops playback while retaining the session. Protected boards, passwords and details use Android's secure-window flag. Rotation/resizing recreates the Activity without revoking the desktop password grant. The replacement Activity restores its selected location/collection, reloads through the existing authorization and applies the secure-window flag before showing protected media. Already decoded previews stay in a memory-only LRU cache, bounded by the smaller of 32 MiB or one eighth of the app heap. Concurrent loads of the same preview share work; recycled cards receive cached bitmaps synchronously. Cache keys separate desktop collection/session/URL and local file modification/size, as well as board/viewer resolution. Configuration recreation retains this cache. Locked, closed, revoked or unavailable desktop collections discard their cached and pending remote previews before showing contents. Closing the app clears the cache and cancels workers; no remote bytes enter the phone's disk cache. Refresh desktop explicitly drops remote previews to fetch changed media at stable URLs.
